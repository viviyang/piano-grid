# 近八轮复核：问题在哪里，方案怎么固定

## 结论

**保留 25 个 URL，一次完成；替换旧 N2D 内容和规则，不推翻 N2A/N2B/N2C。**

[推断] 当前已经投入了共享渲染、family adapter、四音显示、播放、练习和打印。Add9 / Minor Add9 的有界对象集合可以复用这些成果。按既定 24 个具体对象交付，比临时猜哪 6–8 个“最常用”更符合这次已确认的工具字典目标。

这不是搜索收益证明。没有当前关键词量、逐词 SERP 或 GSC 数据支持“25 页一定比 8 页更好”；前一轮我突然建议缩为 6–8 页，同样没有依据，应撤回。不能用凑齐 12 个根音来替代每页的任务与质量要求。

## 1. 页数没有算错，但此前解释和范围管理有问题

[已核实｜实际读取旧包] 旧 N2D 有 24 份详情 JSON、1 份分类 JSON，合并为 25 个独立路由。没有额外 4 个 Add URL。检查结果见 `10_evidence/old-package-diagnostics.json`。

[已核实｜用户 N2C 报告] 报告写 146 个公开业务 URL，151 个构建输出。报告不能支持“已经上线”或“我独立验收了页面”的说法。

**修改：**本包白名单锁死旧 25 条地址。示例、筛选、练习和资产都不增加业务页。171 / 176 只作为无并行变更时的预测；实际用集合合并。

## 2. 我之前先给 25 页、随后又改口 6–8 页，不是有证据的优化

[已核实｜对话记录] 前一轮没有提供新关键词数据、用户数据或内容质量证据，就提出收缩页数。

**修改：**本轮以已确认的参考工具覆盖为决策依据，保留 24 对象 + 1 分类。没有证据就不声称“最常用”“高流量”“SEO 最佳数量”。不另设一个关键词全量研究步骤阻塞这批交付。

[已核实｜外部资料] Google 关注是否给用户价值；大规模低价值、以操纵排名为目的的内容有政策风险，而不是规定某个数字必然正确。来源：`GOOGLE-HELPFUL`、`GOOGLE-SPAM`（07_sources/source-ledger.json）。

## 3. 通过报告不等于我检查过源码、听过声音或确认过 push

[已核实｜用户 N2C 报告] 最近报告明确“未提交、未 push、未部署”。旧 N2D Prompt 却以“N2C 已完成并 push”开头，这个前提没有支持。

**修改：**Codex 读取实际工作树，不设 commit/push 前置。这个包不授权提交或部署；若分支 push 会自动触发部署，也不能把它视为纯保存动作。

自动检查通过、人工审阅、线上发布是三种不同状态。今后确认使用“报告显示通过”，不把工具的 `[已核实]` 标签无条件复制成我的独立验证。

## 4. Add9 与 Add2：原来的教学例子有依据，绝对化推论不成立

[已核实｜外部资料] Open Music Theory 展示上方 ninth 与三和弦内部 second 的区别。Musicca 的 Cadd9 词条同时把 Cadd2 列为替代符号。两份资料的表达侧重不同，不能只保留其中一份就说“所有场景必须只按音区判名称”。

**修改：**保留高、低 added-note 的对照，直接展示确切的 pitches 和 octave。来源两种表述都列出，不声称符号唯一规定所有演奏排列。根音上方 14 半音是本包高位示例的构造约束，不是每一个 Add9 实现的通用合法性条件。

资料：`OMT-ADDED-NOTES`、`MUSICCA-CADD9`。没有复制它们的谱面或图片。

## 5. “组成音正确”与“复现当前音区”不能用同一个判题条件

[已核实｜旧 N2D JSON] 24 页全部只有 exactRealization，并把允许 pitch-class-only 判断设为 false。它可以用于“照图选音”，但不能充当一切和弦识别的定义。

**修改：**

- `Build the chord tones`：比较完整 pitch-class set，忽略八度；允许同音类的八度重复。
- `Match this example`：比较当前图的具体 MIDI set；音区不对但组成音对，提示“音符正确，再匹配当前八度”，不判成“不是 Add9”。

网页任务只说明自己检查的维度，不把点击练习成绩等同于真实钢琴演奏水平。

## 6. 不自动套四个位置，是产品取舍，不是“Add 和弦没有转位”

[已核实｜旧包] 旧 Prompt 要求不显示四位置 selector。这可以避免把 Seventh 的 UI 硬套在新增 family 上。

**修改：**保持不枚举全部转位，但说明本页仅选择两种 root-bass spacing examples。不能由“这批不枚举”推成“这类和弦无法改变低音”或“有其他排列就是错”。两种布局同页比较，不增加 add2 页面。

## 7. 旧内容验证脚本有真实漏检，必须修，而不是再堆通过次数

[已核实｜本次本地实验] 在临时副本里把 Cadd9 的实际 E4 改为 F4，同时同步 MIDI、keyboard、audio、print、practice，保留定义 C–E–G–D，旧 N2D 校验器仍以 0 退出并报告 24/24 PASS。

这说明旧包漏了 definition 与 realization 的成员关系检查。**它不证明用户仓库里的校验器也有这个缺陷**；仓库实现未提供，Codex 可能已加严。

[已核实｜旧 JSON] 旧包 24 个 realization 均缺少显式 realizedDegrees；最高示例达到 MIDI 80，没携带用于该示例的键盘可见范围契约。

**修改：**新包验证音名的字母级数、升降、成员集合、排序、低音、每个示例音区、键盘范围、音频模式、打印映射；增加错误样例测试，证明它能拒绝错误，而非只会接受自己的生成结果。

[已核实｜N2B 原包] 48 页 description 写了 `three inversions`，但输入只有原位、第一和第二转位，即应说 three positions 或 two inversions。本轮需条件查看项目输出；已改正的不要再改。

N2C 旧源还有一个应条件检查的语义点：半减七 source 的 bassDegree 写 3/5/7，而公式为 ♭3/♭5/♭7。若该字段是“序号”可接受；若用于展示或计算“实际音级”，必须分开。**仅检查实际 adapter 的使用，不能据源文件直接宣布线上错误或大规模重写已通过的页面。**

## 8. 大量详情发布，不代表所有工具已覆盖

[已核实｜N2B/N2C 用户报告] Hub 保留 25 个 major/minor 对象，Finder/By-key/Progressions 不自动纳入新 family。这个限制是上一批明确的发布边界。

**修改：**本批继续保持数据边界，Hub 增加 Add 分类入口，不堆 24 张重卡。任何“Find this add9”动作，若工具并不支持则不显示。分类与详情照常可访问；工具范围文案必须准确。后续“全部和弦学习/练习”的目标不能只用 sitemap 数量宣告完成。

## 固定的实施方式

1. 快速查看实际 N2C / 已有 N2D 状态与输入兼容性。不重新做整站规划。
2. 完成 Add adapter、两个示例、两种练习、分类/24 详情/资产/SEO/内链。
3. 有针对性地验证代表案例后，同一轮批量处理剩余对象。
4. 结尾集中跑受影响模块和现有回归，生成 URL 集合差异和结果文件。
5. 无真实阻断不来回问；不自动开始 Extended / Altered，不提交或部署。

旧正确内容、主题与 URL 默认保留。只有已定位到的错误允许修正，并留下修改前后依据。
