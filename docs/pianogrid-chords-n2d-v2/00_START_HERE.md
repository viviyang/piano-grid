# N2D v2：确定方案，一次执行

**最终决定：1 个分类页 + 24 个详情 = 25 个新公开 URL。沿用旧 N2D 的全部地址，不改成 29，也不临时缩成没有数据依据的 6–8 页。**

这是有边界的 Add9 / Minor Add9 产品覆盖决定，不是“25 页最利于 SEO”的结论。12 个参考根音拼写 × 两种性质不等于覆盖所有等音写法或所有 Added-note 和弦。

## 直接使用

把整个包放到仓库：`docs/pianogrid-chords-n2d-v2/`。

在当前 Codex 项目会话发送：

```text
读取并执行 docs/pianogrid-chords-n2d-v2/09_codex/N2D_v2_一次执行Prompt.md。
本轮以 v2 为 N2D 唯一输入，旧 N2D 包不再作为并行执行要求。
先快速适配当前 N2C 工作树，再一次完成全部 25 页；不要每个小步骤都等我批准。
主题、已有正确内容、现有 URL 和已有功能不变。不提交、push 或部署。
```

N2C 不需要先 commit/push 才能处理本包。它必须在当前工作树可用、可构建；Codex 应记录实际状态，不能从旧报告假设它已经 push。若 N2D 已局部实施，原地址原地修正，不创建第二套 URL。

## 改了什么

- 拆开“和弦组成音识别”与“照当前图复现音区”两种练习。
- 每页包含两个明确的音符布局：added note higher / lower，不把 add9/add2 写成通用绝对判错规则。
- 不自动枚举四个转位，但也不宣称 Add 和弦不能转位。
- 补齐 definition → realizedDegrees → MIDI → 琴键/音频/打印的校验及错误样例拦截。
- 保留旧 25 个路由；两个布局、两个练习模式、筛选状态、PDF/SVG 均不额外计作业务 URL。
- 补齐英文内容、TDH、来源、关联表、资产生成输入及一次性实施 Prompt。

## 数量口径

[已核实｜报告支持] N2C 用户报告为 146 个全站业务 URL、151 个构建输出；不是此次重新访问线上取得的数据。

[推断｜算术] 没有其他并行新增时：146 + 25 = 171 个业务 URL；构建仍多 5 项时为 176。和弦系统子集从 133 到 158。

最终数目必须以实际 registry 集合合并计算，不能为了匹配预估数字删其他栏目页面。`01_decision/scope-lock.json` 是本批唯一新 URL 白名单。

## 交付边界

JSON 是经过本包脚本检查的 authoring 输入，不是已经读取你当前源码后导出的运行时类型。Codex 使用现有 family adapter 做最小适配。

本包未在你的仓库运行 build/浏览器/听音/打印。没有附带已经生成的 PDF/SVG 二进制；`06_assets/asset-inputs.json` 供现有项目生成器生成并验收 24 组资产。不能提前显示下载成功或专业教师审阅标识。

近八轮复核意见在 `01_decision/八轮复核与最终决定.md`；本包数据检查及反例测试在 `08_validation/`。
