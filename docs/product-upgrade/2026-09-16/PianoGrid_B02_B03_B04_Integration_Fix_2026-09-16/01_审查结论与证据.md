# 01｜审查结论与证据

## 证据口径

`[已核实]` 表示在所提供截图、源码或测试文件中直接观察到，或在隔离函数环境复现；不自动代表当前生产同样如此。
`[推断]` 表示影响判断、原因判断或改造决定。

源码定位以 B02/B03 ZIP 内 `src/components/keyboard-notes/keyboard-notes-workspace.tsx` 为 `Workspace`。完整片段见 `evidence/源码证据摘录.md`；原样快照见 `evidence/source-snapshots/`。

## 必须保留的完成成果

[已核实] B02/B03 源码已有确定性 preset、三桶结果、复练、原生 dialog、复制降级与共享键盘；不是“这些都没做”。B04 报告与测试文件记录了 compare roles、音频序列、导航/内链、单 base canonical。重新实现这些会扩大本轮范围。

[已核实] 用户第二张图的 `Found it...added to your review` 对应源码 assisted 分支；若之前答错或用过 Hint，这是当前规则下的正常反馈，不能仅凭截图判定计分出错。

[已核实] `Leave practice` 已绑定 `showModal()`，不能凭按钮看起来淡，就判定点击无效。需要修改的是层级、确认框语义、复练退出行为并补测试。

## F01｜分享后修改选项，题组与可点击琴键脱节

**优先级：P0，当前代码若仍存在即阻塞发布。**

[已核实] Workspace L278–294 首次开始优先使用 `sharedPreset.preset`；L415 修改 option 只清空 `roundPreset`，没有解除该优先级；L446 却按新的 option 禁用琴键。

[已核实] 对源码 `startPractice` 进行隔离执行，使用合成 Layout 夹具：共享 `natural-c4-c5`，界面改成 `black-c4-c5`，仍生成原白键题组，10 个正确目标都会被当前黑键模式禁用。反方向也成立。见 `probe-results.json / P02`。

[推断] 修正为一个明确的 active round config。接收者不改选项就还原原题组；一旦主动改范围/题型，解除 shared 锁，提示 `Custom practice`，生成新合法 preset。保持 v1 原生成算法，不让老链接变题。

## F02｜黑键提示错误

**优先级：P1，启用黑键练习时必须修。**

[已核实] `keyPattern(label)` 在 Workspace L49–58 只取 `label[0]`，L453–454 同时用于错答解释和 target Hint。`C♯4` 返回“C is the white key…”，`D♭4` 返回“D is the white key…”；已用源码函数复现（P01）。

[推断] 提示应以实际目标 MIDI、key color、请求拼写、黑键组位置计算。复用 pitch/resolution 与键盘数据，不能只按字母分支。第一次错答只报选择结果，不抢先输出答案；用户点击 Hint 后再输出位置解释。

## F03｜音频按钮与状态转换不一致

**优先级：P1。**

[已核实] Workspace L182–184：播放中换成 stop 图标，但 onClick 始终调用 `audio.play`，没有停止分支。L328–342 `nextQuestion` 没有 `audio.cancel()`；隔离执行确认此路径只推进题目而不调用 cancel（P03）。L135–152 搜索/选择候选也未主动取消旧声音。

[推断] 旧音可能跨入下一题或下一个查阅音。是否实际重叠还取决于当前 `ReferenceAudio`，本轮没有该实现与真实音频设备，不能把风险写成已听到的事实。

修正：显式 Stop 确实停止；换题、换 pair、换选中音、离开、切隐藏 panel 取消旧调度。正常结束不常驻 `Playback finished.`；错误与 loading 保留可见提示。

## F04｜退出复练会清除原始结果；确认框缺少明确语义

**优先级：P1。**

[已核实] Workspace L350–358 `leavePractice` 无条件清除 `savedResult`；question UI 无论普通轮或复练都调用同一确认路径。隔离复现 P04 表明 saved result 被置空。

[已核实] L466–470 的退出 dialog 没有显式 `aria-labelledby`；丢弃操作使用主按钮，保留练习是次按钮。截图中的外部 `Leave practice` 本身不是错误。

[推断] 普通轮：确认放弃本轮；复练：返回并保留原结果，不复用清空本轮的 handler。确认框默认焦点与主操作给 `Keep practicing`；`Discard round` 明确表示丢弃。不要顺手把 Explore tab 改成清除进度。

## F05｜分享 helper 复用了，分享 UI 和失败反馈仍分叉

**优先级：P1。**

[已核实] B02/B03 分享面板写在 Workspace L503–510；原 `ShareControl` 在 share-control.tsx L28–40 仍使用旧行内结构和 `Sharing options opened.`。用户 Labeled 截图正显示该信息。B04 Owner Map 记录“复用 helpers；B04 panel UI”，未证明三处统一成同一 UI。

[已核实] `ShareControl.copy` L32 复制失败让用户复制浏览器地址；但生成 URL 使用组件自己的 params，浏览器地址未必含该状态。Workspace L164–168 重新按物理键 `selectPianoKey` 序列化，导致查 `B♯3` 后复制成 `C4`；P05 用源码复现。

[推断] 抽一个共享 ShareDialog/ShareSheet，外层触发样式可不同。统一复制成功、失败可选 URL、取消安静返回；序列化仍由各业务 owner 负责。查音保留请求拼写；B03/B04 不带用户作答记录。不要把“原生 API resolve”当已发帖。

## F06｜接收者提示抢占首屏

**优先级：P2，用户指定的本轮 UI 修正。**

[已核实] 用户第一张图显示独立大提示区。CSS L107 为 `.kn-v2-receiver-note` 设置居中 max-width、上下 padding、2.5rem 下 margin，与 panel 留白叠加；内容还有两句隐私/内部说明。

[推断] 改成练习标题上方一条紧凑上下文提示，左右对齐练习正文；`Shared practice · 10 notes`。隐私说明移入分享面板或帮助内容，不让接收者读完第二个 Hero 才开始。

## F07｜Labeled 页仍是旧参考壳，不是新的统一体验

**优先级：P2，用户指定的本轮 UI 修正。**

[已核实] 用户第三至第五张图：打印/下载/分享同排拥挤；八度导航长；A0–B0 与 C8–C8 独占大块；页面正文与前面的步骤重复。B02/B03 的测试在 L205–207 只验证切 61 键后总键数，并不是 Labeled 视觉改造验收。其业务组件源码没有进入这次 ZIP。

[推断] 新版屏幕 viewport 与旧完整打印分段承担不同职责，需在不改页面职责的前提下整合。上方一个共享 keyboard viewport + 总览；完整参考按需展开；打印仍覆盖整个所选范围。不能为缩短页面漏掉 A0/B0 或 C8。

## F08｜B04 landing 在猜之前就显示答案解释

**优先级：P1 产品逻辑修正；不是安全漏洞。**

[已核实] `evidence/b04-landing.png` 在未听未猜状态显示“raising only the third by one semitone”，下方还有 A–C–E → A–C♯–E；同时 UI 声称音名会在回答后出现。浏览器脚本只查 `.hd-feedback` 不含 middle，以及 `.hd-reveal` 不存在，没有查整个页面的可见剧透。

[推断] 默认把具体解释收进 `Learn how the comparison works` 原生 details，答后展开。用户主动先打开解释就进入 with-help 状态，不再算无提示发现；说明内容保留 SSR、键盘可访问与相同 URL，不做搜索引擎专用隐藏。

[已核实] B04 单元脚本 L38–49 要求四个 pair 的 answer 全为 `middle`，这是批准设计的局限，不是 Cursor 自作主张。

[推断] 当前定位为引导式 major/minor 听辨对比，不当作重复竞技或耳训成绩测试。保留四组与现有 pair 链接；本轮不扩新题库、不随机低/高音变化。是否另做真正的随机挑战，留后续产品决策。

## F09｜B04 compare 可读性和焦点表现

**优先级：P1。**

[已核实] `evidence/b04-reveal.png` 上 A3/E4 为浅色底加近白字，明显比其余标签难读；还出现不属于该组四个角色的 B3 蓝框。

[推断] B3 可能是 focus、hover 或 selected 残留，凭截图无法确定原因。必须查最终 DOM props/CSS，不把它说成错音高亮的既成事实。共同音、原音、新音和焦点需语义独立，不能靠一组通用 `.selected` 样式互相覆盖。

[推断] 当前字号普通文字按 WCAG 的 4.5:1 检查 computed foreground/background；不从截图反推精确 CSS 值。保留主题蓝，调整角色背景对应的前景色与标记即可。

## F10｜B04 异常截图不等于异常流程测试

**优先级：P1 证据/回归缺口。**

[已核实] B04 浏览器脚本 L121–134 通过 `document.createElement` 与 `innerHTML` 插入 `.hd-audio-error`；新增 Retry 按钮只是视觉示例，没有触发产品失败路径。B04_SCREENSHOT_DIFF.md 也承认是注入截图。

[推断] 该图可作为外观证据，不能证明加载失败、Retry、取消旧队列与禁止解锁猜测正常。必须通过模拟 AudioContext 失败/真实 owner 边界失败进入业务状态；禁止插 DOM 来替代断言。

[已核实] B04 51 项结果未包含 Clipboard 拒绝、native cancel、不支持 share、后台中断等完整边界；B02/B03 原 79 项也未包含修改共享选项、黑键提示、退出复练。这解释了“全绿仍有缺陷”的覆盖盲区，并不说明既有用例没价值。

## F11｜交接和回归范围不够覆盖最新共享改动

**优先级：P1 交付要求。**

[已核实] 两包 hash 已核对。B04 ZIP 共 33 个条目，包含报告、截图、两个 check 脚本；没有 `src/` 业务文件或完整 diff。它不能用于本次独立逐行复核音频 hook、比较角色、元数据实现。

[已核实] B04 修改点包含 `KeyboardDiagram`、`share-control` 等共享文件，但其报告未记录在 B04 改完之后重新执行 B02/B03 的 79 项浏览器回归。B02/B03 package.json 中 `npm run check` 仅含 foundation/typecheck/css，不自动包含该浏览器脚本。

[推断] 本轮最终必须在同一个最新状态执行新用例 + 两批原有用例，并把最新共享文件、B04业务源码或完整 diff纳入交接。不能将不同时间点的 PASS 拼成“最新整合验证通过”。

## F12｜文档的 canonical 结论过强

**优先级：P2 文档纠正，不改 URL。**

[已核实] B04 route plan 将 query 写为“not indexable”，同时声明 base canonical 与 index/follow。

[已核实：外部核验] Google 把 canonical 作为规范化信号，声明 canonical 不等于 query 被技术禁止索引。

[推断] 改写为“query 仅承载状态、不进 sitemap、声明 canonical 至 base”；不要为了修文字随意加 noindex 或 robots 屏蔽。B04 新页动态渲染记录单独保留，不仅凭动态/静态标签推断 SEO 好坏。
