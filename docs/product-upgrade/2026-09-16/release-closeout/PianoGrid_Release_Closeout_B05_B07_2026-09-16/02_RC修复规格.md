# RC01–RC08｜限定修复规格

本文件中的操作是实施决策，不是声称代码已改。优先复用现有owners；不得复制演示引擎。

## RC01｜把组件的样式也真正共享
**定位**：`hear-the-difference.css`、`share-control.tsx`、`keyboard-notes.css`、`keyboard-notes-v2.css`、`labeled-experience.tsx`。

1. 按批准B04 v2恢复hd-presets/preset、hd-three、hd-content、hd-refs/outbound、hd-reveal-actions、hd-preview等基础布局；不能只补mobile media query。4个pair桌面可分四列、手机两列，实际按已有稿；每个按钮是独立可见操作，文本不相连。
2. 提取ShareDialog/Panel、manual-link、状态槽等必需样式到现有共享样式owner，由共享组件导入或在稳定公共layout统一加载；不得把全部Keyboard页面CSS导入B04。
3. 对话框继续用原生dialog。桌面居中，手机底部面板；宽度不超视口、最大高度和滚动受控，保持项目圆角/间距/颜色变量。Close、copy、native share不能缺失或挤出。
4. 共享范围总览高度直接作用于总览组件，不依赖某页面祖先。概览不作为第二个可演奏键盘；标注范围、对键盘用户不过量制造无用焦点。
5. Labeled Print应用已有primary类；其余次级操作不和primary争权重。移动黑键label使用nowrap与足够最小键宽；必要时局部水平滚动并保留范围导航，不允许页面整体overflow。
6. 删除用户可见原始sourceID堆叠，改为展开的来源名称/链接；使用现有registry。没有名称可核实的记录留在内部待补，不编造。
7. 这批不改全站字体、品牌色、Logo、导航层级，也不批量迁移Chord/Scale键盘。

## RC02｜统一练习入口与视口恢复
**定位**：Workspace初始化、Labeled入口、现有URL解析owner、viewport。

- `/keyboard-notes`默认Explore。
- `/keyboard-notes#note-trainer`必须直接进入Practice开始状态；保留已有hash作为兼容入口，不新增路由。
- 合法v1 practice query优先恢复题组；非法v1进入可用的“链接不可用/新练习”界面，不挂起页面。
- hashchange / 浏览器前进后退恢复可见模式。URL同步不删除当前有效分享参数；有未完成round时按现有保留/退出规则执行，不能静默清空。
- id存在且可见后再定位。不能只scrollIntoView隐藏section。
- 来源入口统一由一个小型helper生成；Teacher PDF、Labeled、Tools复用；不得在各页手拼不同的practice参数。
- Explore从外部恢复A0/F3/C7等音时，完成compact断点同步后仍将目标音保留在窗口内。调整屏幕宽度/横竖屏不固定重置到C4导致已选音消失。

## RC03｜音频任务与页面任务使用同一有效请求身份
**定位**：B04 experience/use-comparison-audio、ReferenceAudio现有接口；不重写音频引擎。

- 在当前owner增加runId/generation令牌；每个await之后、finally解锁之前验证仍是当前pair当前run。旧run不改新run的busy、phase、error或完成事件。
- Wrong/Hint重播期间禁用Hint和Show answer。即便事件已入队，handler也要检查busy与request身份，不能靠按钮disabled充当唯一保护。
- 切pair、Stop、页面隐藏/卸载使旧run失效并停止音频。新pair保持landing直到本pair两段完整完成。
- 揭晓后允许Replay，但completed不能把reveal变成ready。合法转移必须显式表达，避免依赖旧闭包里的phase。
- 底层完成契约先查看ReferenceAudio源码。利用已存在的返回值/状态回调组成typed result，禁止`as unknown as {state?:string}`猜字段。
- 两段都成功播放完成才返回completed；第一段失败不播放第二段；第二段失败不能启用猜题；取消不作为错误也不记completed。
- 统一Play/Stop入口；避免两个同名Replay按钮同时成为主操作。

## RC04｜整页解释披露与帮助状态
**定位**：B04所有用户可见内容，不只challenge/more两个容器。

- Landing可保留一般规则和网页标题；默认不能展示“third/middle是答案”、具体前后音名、固定根/五音等明确解答。
- 将具体“at the piano”步骤与interval explanation放在同一个受控`Explanation`区域；首答前默认关闭，可由用户主动展开，展开即标记helpUsed。
- 所有答案型details都连接同一披露事件；不能漏掉第二个details。切换pair时关闭并重置本轮帮助记录；若刻意保留展开则必须继续算help，不能开着答案却算独立。
- 成功但用了帮助，反馈为“That's the changed voice.”或“Comparison explained.”；不再说“You heard…”来推断真实听觉能力。
- 揭晓区域优先下一pair，其次分享、参考链接。保持“固定root-position close voicing”的边界；这四例都改third，不是随机耳力测验，不新增排行榜或分数。

## RC05｜共享UI与打印的生命周期
**SharePanel / Dialog**
- url/title/payload身份变化，清空上一对象的message和manualURL。每次打开新面板也清理旧成功状态。
- 复制失败时textarea始终显示当前`url`，不要保存永远不更新的副本；已完成的旧异步copy任务不得给新payload写成功状态。
- share取消安静结束；原生分享失败仍提供当前URL。用户选择复制后切pair的竞争路径也测试。
- 关闭恢复实际触发按钮；来自Copy fallback的焦点返回Copy，不固定返回另一个Share按钮。

**Explore**
- Find提交前（成功、非法、音域外都包含）取消旧音频；选择新音、布局、模式遵守同一契约。避免视觉已经变了旧音还持续。

**Labeled print**
- `beforeprint`捕获当次layout/octaves；`afterprint`清空snapshot。UI按钮与Ctrl/Cmd+P采用相同数据源，不额外复制print engine。
- printPart在当前布局合法范围内才应用；非法值回退全部，而不是空白打印。布局变化使无效part失效。
- 不改既有Letter landscape全范围参考的定位；新B06资源的打印尺寸以后独立scope，不能污染现有输出。

**Practice轻收整**
- 复练终点明确“Review complete. Your original result is unchanged.”，不重计原分数。
- 开始/换题/结果/返回原结果时明确可用焦点；用程序可聚焦标题或主操作，避免Next按钮卸载后键盘焦点掉回body。原生dialog的关闭焦点按APG复查。

## RC06｜验证真实音频失败，而不是只验证测试flag
[已核实] 当前`__hearForceAudioError`分支在调用ReferenceAudio前返回。

- 替换成测试层注入：组件/owner测试可用可控audio adapter；浏览器测试在真实使用的平台/资源边界制造失败（例如实际owner会调用的resume/decode/network边界）。必须走业务真实错误回调。
- 不通过DOM插入错误框，也不直接set React error来宣称底层失败通过。
- 测第一段失败、第二段失败、resume拒绝、用户Stop、后台取消、Retry完整成功。
- Retry不只是“错误框消失”；等待两段完成，校验两段调用顺序/无旧音源、答案可用、完成事件仅一次。
- 删除生产中无条件读取的全局调试flag；需要的可控测试seam保留在测试依赖层，不交给用户query触发。
- 音频资源/平台细节以当前ReferenceAudio为准；不得为了测试新增大音源或换引擎。

## RC07｜把当前dirty工作树封成可恢复交付
- 修复前先保存本轮相关tracked、staged、untracked文件清单和内容哈希；当前HEAD是B02/B03，不能当作“修复前B04”的完整镜像。
- 分开记录`HEAD→release candidate`与`pre-RC→post-RC`两个比较口径。要么有精确快照文件，要么有可应用补丁；不要把两种差异混称FULL。
- git stdout写入patch，stderr写入log，不再`2>&1`污染patch。包含binary安全信息；新增文件用untracked内容manifest或完整scope快照补齐。
- B04路由、pair数据、events、OG生成、site wiring、新viewport、测试、必要导出资产必须在scope里。不是只导出`git diff`里的tracked文件。
- 包含实际raw JSON、commands/exit codes、截图索引、BASE_SHA、文件哈希。`testCount`不代替用例证据。
- 在一次临时目录/工作树做恢复演练，不能在当前dirty树reset。禁止覆盖.env、密钥或无关Home/Songs修改。
- 发布rollback只针对已批准release artifact或精确pre-RC snapshot，不能泛泛“从git恢复”而删除未提交B04。

## RC08｜完成行为验收，不凑PASS数量
- 黑键题目标要从pitch解析/MIDI和真实layout验证；删除`|| /[CDFGA]/`这样的宽松通过条件。
- 十题每个target都对应可点击键。共享→改option→再分享→接收者还原，包含全部option和布局。
- 页面无overflow不能代替移动黑键字不换行、ShareDialog尺寸、pair卡片grid、Labeled概览高度。
- 对每个验收case输出`PASS / FAIL / PENDING_MANUAL / BLOCKED`和证据；不把PENDING算PASS。
- 同一release candidate重跑B02/B03、B04、Tools、Foundation、build、diff check；不为通过随意修改硬编码URL数量，先记录“公开URL/构建输出/系统页”的口径。
- 本轮不引入新统计平台；核查事件是否真正有collector。若只是CustomEvent，就写`INSTRUMENTED_NOT_COLLECTED`，不得承诺可见真实漏斗。接入已有已授权provider属于小适配；新provider/账号不自动开通。
