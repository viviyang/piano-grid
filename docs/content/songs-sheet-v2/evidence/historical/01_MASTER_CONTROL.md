# PianoGrid｜总控计划与共同约束

2026-09-14 · v2.0

本文件负责“做什么、什么顺序、如何交接与判定完成”，不是第二套全站 URL 规划。

## 1. 固定目标与当前事实

[已核实｜用户要求] 产品范围保持：**Chords、Scales、Keyboard Notes、Beginner Songs、Sheet Music、Practical Tools**。用户希望主要钢琴查询、初学、练习、取谱任务在一个站内完成，并考虑有用、愿意分享、流量与变现。

[已核实｜用户本轮说明] 网站刚上线、数据少；Scales 正在实施，预计 2026-09-14 完成。不得把这一预计写成验收通过。

[已核实｜用户提供的历史报告] Chords 已有完成报告及 PASS_WITH_NOTES。那是已有报告的状态，不是本轮重新认证所有代码与线上功能。

[已核实｜本轮公开页面] Keyboard Notes 有查音与播放入口；Tools 已连接多类查询与打印资源；Songs 的抽查条目明确属于外部版本参考。公开页面读取不能替代本地实现、真机听音和打印验收。[S1–S3]

**总目标保留“月流量至少 30 万”。**
[推断｜统计建议] 工作台以近 30 个完整自然日的 sessions 记录“访问”，PV 与自然搜索 sessions 单列，不偷偷改成必须有 30 万自然搜索会话，不把曝光或视频播放算成站内访问。

不设未验证的到达日期、固定 RPM 或收入保证。不用“缺少后台数据”阻塞明确产品任务。

## 3. 执行顺序与并行规则

| 阶段 | 主开发交付 | 可并行的规划/内容工作 | 进入下一阶段的条件 |
|---|---|---|---|
| 当前 | Scales 按现有包实施 | Keyboard 专项；Songs 版本/权限/内容准备 | Scales 停止写代码、结果与待办交代清楚；关键共享缺陷先处理 |
| A | Keyboard Notes 产品完成 | Songs 数据与资源准备；Tools 盘点 | 本批批准任务完成或明确阻塞；不需要等待有搜索流量 |
| B | Songs＋Sheet Music 同批交付 | Tools 专项；互联关系表补齐 | 发布候选的曲目、谱面、音频相符，权限与产品测试有证据 |
| C | Tools 整理和真缺口 | 全站关系验证 | 每个承诺工具都有实际落地任务，没有重复引擎 |
| D | 六模块最终联验与商业接入检查 | 下一批原规划任务 | 六类代表任务可用、关系正确、上线状态明确 |

同一工作区一次只有一个实施会话写业务代码。ChatGPT 的研究、规划、内容核查可以并行。
不为“全部齐了”等待所有内容才发布；每个满足条件的批次在获得部署授权后独立上线。
Song 资源的局部权限阻塞不能拖住 Keyboard 或工具整理；必要时调整代码执行次序，并保留阻塞台账，不把未完成删除。

不再人为排固定六周。每个专项在看到实际缺口后按“小改/中改/大改”估工；能一天交付不拖成一周。时间不足只诚实拆批，不降低准确性和权限要求。

## 4. Chords 的“收尾”精确定义

只确认三件事：

- 最新有效报告中，是否仍有影响查和弦、音符/键位/音频/打印、链接可达性或发布的未结问题？
- 这些问题是否已经在之后的改动或现有技术审计中解决？
- 尚未解决的内容，是当前功能缺陷，还是以后新增的分享/搜索/商业能力？

无已知阻塞：写 `NO_ADDITIONAL_CHORDS_WORK`，移到维护状态，不额外开发。
有已复现问题：写复现、影响范围、最小修复；只处理该问题，不能扩大成第二轮补全。
证据不足：写 `UNVERIFIED`；只补必要证明，不假装功能有问题，也不假装已通过。

Universal Search、教师账号、所有歌曲的和弦关联、付费包、全新练习模式均不属于“Chords 收尾”。它们按实际职责归 Tools、互联或商业任务。

“没有额外收尾任务”不等于“永远没有 bug”，也不等于“用户价值和收入已经验证”。

## 5. 六模块职责和互不重复的边界

| 模块 | 用户任务 | 负责的数据/功能 | 本批不能冒充完成的事项 |
|---|---|---|---|
| Chords | 找和弦、看构成、听/比较、获取参考 | 已有和弦实体、Finder、转位与已有参考能力 | 不因需要增长而重做正确内容 |
| Scales | 查形态、看音符/已证实指法、听/练/打印 | 以正在实施的批准方案为准 | 不缩成样板，不把播放走完叫弹对 |
| Keyboard Notes | 找音与八度、琴键和谱面关联、基础自测与打印 | Notes 实体、键盘布局、该模块训练器 | 不与 Tools 各建一个查音引擎 |
| Beginner Songs | 选择适合的具体版本，知道怎么开始弹 | work/arrangement、难度依据、练习步骤 | 外部参考不是本站托管的学习版本 |
| Sheet Music | 预览、辨认版本和权限、获取或打印 | 同一 arrangement 的 score/audio 资产与获取方式 | 不能用付费外链冒充免费本站 PDF |
| Tools | 快速完成一个操作任务 | 复用前述能力，整理入口，补已批准缺口 | 不为了工具多而复制页面或造十个引擎 |

Songs 与 Sheet Music 分开页面职责、共用同一具体版本的资产。前 3 个完整学习版本是优先交付建议，不是永久缩小范围，也不是已批准可复制的曲单。原方案其余曲目和内容继续保留。

## 6. 新专项必须按什么顺序产出

**当前证据 → 竞品任务差距 → 原规划映射 → 完整范围与分批 → 内容/数据/来源 → 页面与交互 → 传播/变现 → Codex 实施 → 验收。**

不再做全量关键词清洗、全市场 Deep Research 或无止境竞品列表。
每个专项至少检查 2 个相关竞品的实际页面；找不到可访问的依据就写未核实，不用搜索摘要假装实测功能。
竞品某项功能存在只证明它提供了该能力，不证明该能力带来流量或收入。

每个专项应给出一份执行包：

| 内容 | 必须包含 |
|---|---|
| `PLAN.md` | 已有/修复/补充/后续/阻塞；URL职责映射；逐项验收；本批批准范围 |
| `content-data/`（需要时） | 实際整理好的英文文案、结构数据、来源/权限；不仅是“请Codex去找” |
| `CODEX_PROMPT.md` | 能直接在仓库实施；只对真实新增高风险范围请求决策 |
| `RESULT.md` | 由实际实施者生成，规划模型不能提前填PASS |

已有等价文件就复用，不为了名字不同重复做材料。资料缺项不妨碍的部分先完成；影响代码契约的最小缺项在实施前定位。

## 7. 共同技术与产品规则

**路线不重做。** 沿用原 `Piano_全站统一规划_最终版.md`、`url-plan.final.json` 和之后明确批准变更。哪个文件有效依据内容与批准关系，不只看“final”或文件时间。

**设计不重做。** 沿用当前品牌、主题、Hero、设计变量、认可样板。不做四版视觉，不升级依赖，不为了统一引入另一套组件库。

**代码先复用。** 真实组件路径、API和数据类型由Codex从仓库确认；规划对话没有拿到源码就不能编造路径。共享能力采用现有结构的最小适配，不预设必须迁移为新的数据平台。

**数值不混用。** 对象数、公开路由、sitemap URL、构建输出、导航链接分别统计，历史的173/158等不能当当前硬编码断言。

**功能诚实。** 查音/测验结果不等于实际钢琴演奏准确率。没有MIDI/麦克风识别就不宣称听见用户弹奏。没做真机、实体打印和专业审核就写未做。

**页面有独立任务。** 不把同一工具状态拆成索引页，不用几百个URL保证流量。Title/Description/Headings对应真实内容，不强制词数或关键词密度。Google也没有保证排名的固定字数秘诀。[S8–S9]

## 8. 互联规则现在就定，不等最后

每个模块提供：`entity_id`、`entity_type`、`canonical_url`、`availability`、相关对象ID、已支持分享状态、资源/权限状态、已有测试证据。字段名称可映射现有实现，不强迫重命名。

关系必须说明：**为什么相关？目标是否可用？这条关系是否有数据依据？**
不能因为某曲“在C大调”就自动写“使用所有C大调和弦”；必须对具体版本有依据。

分享按现有支持状态还原结果，不发明私人作业数据库。参数不是新SEO页面；常规内容页保留自己的规范URL。

每页只给对当前任务有帮助的下一步，不要求每页都挂六个栏目。已有正确内链继续用，最终联验做查漏和纠错，不重新建导航。

## 9. 统一完成标准与上线边界

| 状态层 | 证明什么 |
|---|---|
| 范围完成 | 每个批准任务都有交付、后续或具体阻塞，没有静默遗漏 |
| 工程通过 | 实际命令、数据、交互、回归与版本证据 |
| 内容可发布 | 准确性、来源、权限符合该内容的要求 |
| 人工检查 | 真实设备、听音、打印、读屏等适用检查已做或明确未做 |
| 线上通过 | 明确部署版本与线上代表任务，不能用本地build代替 |
| 用户/商业验证 | 实际观察、传播落地和收入；没有证据标未知，不阻止合格产品继续开发 |

P0：错误音符/权限不明资源上线/支付不交付/关键功能不可用等严重问题，阻止对应内容或功能发布。
P1：重要任务在支持环境中无法完成，需明确受影响发布范围。
P2：非阻塞的改进，不作为无限拖延下一模块的理由。

不提交、不推送、不部署、不改DNS、不安装付费服务、不收费，除非当前具体执行任务已有对应授权。用户已明确批准的正常小范围实现不要反复请求相同授权。

## 10. 谁做什么

| 责任方 | 负责 | 不宣称拥有的能力 |
|---|---|---|
| 当前ChatGPT总控 | 维护顺序、范围、跨模块规则、商业目标，解释执行结果并调整任务 | 不声称后台自动跟踪或直接控制未连接仓库 |
| 四个专项ChatGPT对话 | 本模块竞品、内容/数据、功能规格、Codex包 | 不默认读到本地文件，不代表法律或专业审核机构 |
| Codex实施会话 | 读取仓库、实现批准内容、运行测试、更新实际结果 | 不伪造生产检查或真人测试 |
| 独立验收会话 | 对实际diff与批准目标复核，报告可复现问题 | 不与实施会话同时改业务代码 |
| 用户 | 关键产品决策、必要人工测试、账号/收款与发布授权 | 不需要重复写每个模块计划 |

本轮只建立可更新机制，没有创建自动化后台任务。后续将模块 RESULT/变更摘要放回总控对话即可更新安排。
