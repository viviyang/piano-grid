# PianoGrid 前端组件规则

版本：2026-09-21。适用于所有 agent 的页面、组件、样式实现与审查。此文件是组件规范的唯一维护源；工具入口只保留引用。

## 适用范围与依据

- 先读取根目录 `AGENTS.md`。当前用户明确授权决定任务范围；本规范不授权扩展产品功能、修改音乐数据、全站迁移或发布。
- 视觉依据为本任务最新明确批准的设计与项目 tokens；没有新批准时沿用 `docs/design/design-system.md`、`src/styles/tokens.css`、`src/styles/foundation.css` 及对应页面的只读参考。规则本身不授权重新设计。
- `design-system.md`、`inspection.md` 含 Foundation 初始化历史。“不创建组件”“尚无页面”等阶段描述不能当作当前实现禁令；安装状态以当前源码、`package.json` 和锁文件核实。
- [已核实，2026-09-21] 本次核对时仅有 shadcn 配置入口，没有 Button、Input、Dialog 等 shadcn 组件源码。`components.json`、目录名 `ui`、依赖里有无名为 shadcn 的包，均不能单独证明组件已引入。
- [已核实] shadcn 提供可修改的组件源码与分发机制，适合作为项目组件实现来源；不要求采用其默认外观。官方依据：https://ui.shadcn.com/docs （核对日期：2026-09-21）。

## 写页面前的选用顺序

1. 搜索 `src/components/ui`、相关业务目录、共用 CSS 和真实调用点，记录本次需要的交互及可复用组件。不能只凭组件名称判定适用。
2. 已有组件满足语义和行为时优先复用；缺少状态或变体时，优先在兼容现有调用的前提下扩展。
3. 缺少通用组件时，必须评估 shadcn 对应组件，并与原生 HTML 方案比较。复杂弹层、菜单、组合框、Tabs 等优先考虑成熟实现；记录采用或不采用的简短理由、实际所需依赖。不得未检查就重新实现焦点管理或完整键盘交互。
4. 原生元素已满足任务时允许使用，通常封装项目统一样式。简单 select、checkbox、radio、details 不因 shadcn 有同名组件就必须替换。语义和行为优先于外观相似；选择器不能仅因长得像 Tabs 就改成 Tabs。
5. 钢琴键盘、谱表、指法、音符及音频业务保留领域组件；通用控件可以组合到领域组件中。

评估结论在任务说明或交付中简述即可，不要求每个按钮建立审批单。所需依赖未获授权时先完成可独立推进的工作；不能用不完整的手写复杂交互规避依赖限制。

## 共享组件和页面边界

- 通用控件放在 `src/components/ui`；音乐业务组件留在所属业务目录。页面负责数据与组合，不复制已有基础交互实现。
- 同语义、同状态规则的代码在第二处出现时进行复用审查；能稳定共用就抽取。业务语义不同或抽象会增加大量开关时允许分开，注明理由。重复的原生标签或共享 CSS 类本身不等于重复实现。
- 不提前生成整套未使用的组件。优先处理本次真正需要的 Button、IconButton、字段、弹层或折叠组件。
- 组件 API 应保持原生属性、可访问名称、事件和必要的 ref 能力；按钮执行动作，链接负责导航。不渲染嵌套 button/链接等无效交互结构。
- 已有共享组件可直接复用；新增基础组件后，本次新增的同类控件使用它。历史页面按授权范围逐步迁移，不为规则落地顺带重写全站。
- 只在需要状态、事件或浏览器 API 的最小边界使用客户端组件，避免将整个页面转成客户端。

## 视觉与交互合同

- 采用项目语义 tokens，保留已有主/次/文字操作的层级。不照搬 shadcn 默认字体、颜色、圆角、阴影、动画或暗色模式；不要新增一套并行主题。
- Foundation 默认控件圆角 8px、面板 12px、普通按钮最小命中区 44px、全局焦点轮廓 2px。更细的分段、键盘、打印等差异按相关设计合同执行；不得把普通按钮尺寸强套琴键。
- 保留 hover、focus-visible、selected、disabled 及适用的 loading/error 状态。选择状态有正确语义和非纯颜色标记；禁用必须真正影响行为。
- 原生 label 与字段关联；图标按钮有可访问名称；复杂组件检查键盘操作、焦点进入/返回、关闭行为及读屏语义。采用 shadcn 或原生元素不代表整个页面已通过无障碍验收。
- 正文不因存在 Card 组件而统一卡片化。布局与内容结构遵循页面职责；支持窄屏、文字放大及适用的 reduced-motion、forced-colors 和打印行为。

## shadcn 与依赖边界

- 保持 Tailwind v4、现有 `components.json` 和 CSS 入口；不运行 `shadcn init`，不覆盖全局 CSS、tokens 或已有组件。
- 默认仍不新增或升级依赖。本次更新规范不包含安装授权。用户已明确批准引入某组件及必要依赖时，可在该范围内连续实施，无需逐包重复询问；只添加必要依赖，保留锁文件和既有框架版本。
- 引入前核实该组件当前源码及其实际底层依赖，不把所有 shadcn 组件一概视为 Radix，也不混用多套交互基础库来完成相同职责。
- 按需添加组件、审查生成差异、适配 tokens、记录来源和引入时版本或修订信息，保留许可证要求。不得为了修复样式批量更新其他组件或依赖。

## 验证与交付

- 实现前简述本次复用、扩展、新增及例外选择；普通实现选择自主推进。
- 改动代码后运行适用的类型、CSS 与项目检查；共享组件修改须检查受影响调用点，交互修改须验证键盘、焦点和代表性桌面/移动布局。仅规则文档变更检查引用、冲突和 diff，无需运行整站构建。
- 按 `AGENTS.md` 和当前任务要求执行必要检查，报告实际运行结果与未验证项。不要因为使用组件库就声称读屏、真机、打印或整体无障碍已通过。
- 交接注明本规则版本、修改的组件、影响范围和验证状态。无法自动加载项目规则的宿主，应在任务上下文显式提供 `AGENTS.md` 和本文件；不得宣称所有工具已自动读取。
