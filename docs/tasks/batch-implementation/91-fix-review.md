# 91 — 按审查报告修复并回归

你在主开发对话执行。先读MASTER-RULES与进度表，再读取用户指定的review.md；未指定时定位当前批次最新明确审查报告，不能猜另一个分支报告。

只修本批已授权范围内的真实问题，不借机重设计/升级依赖/改内容。核对报告所审版本是否仍对应当前源码；过时的问题先复现，不为“顺从审查”制造回归。

按P0→P1→P2处理。先复现再修复并补回归；视觉建议不等于授权换主题。范围、音乐事实、版权用途或依赖决策超限时记录最小确认问题，其余独立问题继续。

未确认的指法/版本不能当代码Bug“补齐”。源文件仍保持只读。

修后运行相关测试、A minor必要回归、check/build，补充当前截图与文件哈希；不能以修改期望值来掩盖差异。

写入 `checks/batches/<批次ID>/fixes.md`：每个review ID的复现、修复文件、复测证据或不适用理由。更新进度表为等待复验，不由自己伪造独立review通过。

完成后停止；交独立验收对话复验。不得自动进入下一批。
