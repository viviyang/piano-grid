# Piano Reference — 组件设计、复用基建与页面模板补充规则

> 用途：补充已提供的 `docs/tasks/batch-implementation/MASTER-RULES.md` 及 00–07 批次任务；不是重做 Foundation，不是新增产品规划，也不是批准全部路由。
> 建议放置：`docs/tasks/batch-implementation/COMPONENT-TEMPLATE-RULES.md`。
> 在已授权的当前批次内执行；不因为读到了本文件而实施尚未授权的后续页面。

## 1. 本轮要纠正的执行方式

禁止将批量开发理解为“每个 URL 写一份 JSX，再统一套全局 CSS”。
执行顺序应为：

已有 Foundation 与成品检查 → 内容接入 → 组件盘点与模板映射 → 当前批次的必要组件提取/补充 → 模板代表页验证 → 同模板实例接入 → 每页数据及共享代码回归。

00 已完成就复用结果；01 已开始就从当前差异继续；01 已完成就先核验是否已满足本文件，缺什么补什么，不整体回滚或重做。不能仅因组件命名或文件夹与示例不一致而重构。

普通组件实现无需逐项向用户确认。没有依赖变更、范围变更、真实数据冲突或明显视觉偏离时，完成本文件在本批的要求后继续原已授权任务，不停在架构文档。

## 2. 先检查，不假定已有成品缺少组件化

读取实际 AGENTS、Foundation 规范、已完成 A minor 源码、验收记录与当前任务进度；读取规划和最新 site-master 内容包及 integration_contract。

在代码改动前记录：
- 已有组件、hooks、内容适配器、音频调度、打印流程、路由与元数据的实际位置。
- 当前有无重复 JSX/样式/状态；组件已复用时保持，不另造平行版本。
- 已完成页面的桌面、手机与主要状态基线；已存在的问题另列，不伪称本次引入或已通过。
- 已有依赖与测试工具；不为套流程重新 init、升级、安装全套 UI 组件。

原始 docs/product、docs/content 和设计参考保持只读。不能用旧 batch-01 的待制作状态覆盖最新 master 的内容准备状态；内容已准备也不代表当前代码已经通过验收。

## 3. 架构分层：职责先定，目录服从现有项目

### 3.1 Foundation

沿用现有 tokens、字体、尺寸、断点、focus、cn 与 Tailwind 映射。除复现到的接入错误外不动全局视觉规则，不再选择 Apple/Spotify/Linear/Claude 风格。

### 3.2 基础 UI 与站点结构

按当前用途提取/复用：按钮及链接外观、表单字段、单选分段控件、Disclosure/FAQ、状态提示，以及已有 Header/Breadcrumb/内容容器。

已有语义正确的原生或 shadcn 实现优先复用。选中转位是单选参数，不能因为视觉像 tabs 就改变语义。不要另外做一套同职能 Button，也不要安装暂时不用的组件。

Header/Footer 在实际多页使用时共享，不必等 07 才消除副本；07 仍负责首页、工具中心及完整导航联调。共享站点结构不等于提前实现 `/`，不新增全站搜索，不开放未授权目标。

### 3.3 音乐领域组件与行为

本批应检查/提取：KeyboardDiagram、音名/音序显示、PlaybackControls、受控声音逻辑、PrintActions、和弦摘要/结果。

抽象共同事实与机制，不虚构未来能力：
- 图形层根据输入的范围、键位与标签绘制，不自行生成未提供的和弦或指法。
- 保留书写音名、音区、物理音高标识，不因物理键相同合并等音拼写。
- 表现 selected、root、bass、sounding 时遵守实际数据和成品基线；缺少正式视觉定义的差异单独报告，不擅自换外观。
- 键盘默认参考图；琴键页的主动点击定位只在该批获批时启用，不回流成 A minor 的新功能。
- 从现有声音实现抽取必要复用，保持原事件频率/时序；共享显示控件不代表各页面必须有相同业务操作。
- 单个工具的业务选择由一个明确父级拥有；中心页的筛选、当前对象与发声对象分别建模，再派生结果。
- 同页面多结果播放必须互斥，切换结果/过滤/路由/卸载取消旧音与回调；不增加全站常驻播放器。
- 打印调用可共享；当前单项、一组和空白谱纸的版式与输出合同不强行合成一种布局。白底、页边距等共性可以复用。

### 3.4 任务模板

模板负责按某种页面任务组织数据、工具、解释与资源；不得用“一个通用标题+任意 blocks 循环”替代原任务。

模板接口只接收本页需要的数据。新旧内容分别通过只读适配器转换到本页/本领域的显示模型；保留 provenance、URL、template_id、source_group、block_id 映射。

不要把所有音乐、歌曲、谱面与教程数据压成同一种 optional 字段集合。不要为了强行统一 schema 重写原两页。

`ChordDetailPage` 等是普通 React 页面组成组件，不要求创建 Next.js 特殊约定的 `template.tsx`。沿用现有路由方案即可。

### 3.5 路由实例

路由负责：授权范围校验、读本页数据、准确元数据、选择对应任务模板。

可保留多个很薄的 page.tsx，也可使用受严格白名单约束的动态路由。不强制为“架构好看”迁移路由结构。

不通过 master 的存在自动暴露 URL；没有本批授权的对象不得进入生成清单。不能让其他页缺失数据时退回 A minor 作为假答案。

## 4. 组件设计必须覆盖什么

每个实际复用组件记录简短契约，不仅写名字或列目录：

| 字段 | 应说明 |
| --- | --- |
| 职责与调用方 | 服务什么任务；哪些页面/模板真正使用 |
| 数据接口 | 必需/可选 props、回调、来源和缺失处理 |
| 变体 | 只做已使用的尺寸/外观；例如主结果图与列表图 |
| 状态所有权 | 谁决定选择、加载、播放；哪些值是派生而非另存 state |
| 状态表现 | default、hover、pressed、selected、focus、disabled，以及适用的 loading/error/playing |
| 响应式 | 断点中的布局、标签、触控、溢出策略，不简单缩小 |
| 语义与无障碍 | 原生语义、名称、键盘操作、焦点、不仅依赖颜色 |
| 打印 | 是否出现、是否使用独立 print renderer，输出数据来源 |
| 验证 | 对应测试用例与真实截图；明确未测 |

不要求每个组件实现不适用的状态。例如静态容器不需要 loading，参考键盘不需要假的 hover 点击效果。

KeyboardDiagram 的“列表版”不能仅把大图缩小到音名不可读；必须结合列表可用宽度、完整音序文字、必要局部查看检验。

根据实际 url-plan.final.json 建立 URL → template_id → 模板职责 → 共享组件 → 内容适配 → 状态 → 验收映射。

不改变原 T 编号。23 个任务模板不等于必须立即写 23 个独立 .tsx，也不等于每个模板都只对应一种页面布局。

以下是按现有规划的参考映射，读取本地正式文件复核后使用：

| 规划 ID | 任务 | 实现策略/时机 |
| --- | --- | --- |
| T06 | 和弦中心 | 01 实现独立中心模板；复用键盘/声音/打印，不复制详情页布局 |
| T07 | 具体和弦页 | 01 检查并复用 A minor；A major/C major 是真实第二/第三实例 |

| T11/T12 | 音阶中心/具体调性音阶页 | 03 形成两类模板；形式、方向、手别等按真实内容支持 |
| T15/T16 | 选曲中心/专题 | 04 共享作品/版本/资源条目；中心与专题保留不同任务和分区 |

矩阵登记全站不等于批准全站开发。共享代码不等于共享正文；每页用自己的事实、解释、步骤、FAQ 和素材。

## 6. 本次 00+01 怎么落地

### 00 内容接入补充

在原内容接入步骤中增加组件盘点与模板矩阵。完成新旧内容读取适配，保护现有 A minor，记录待抽取项。

### 01 的内部顺序

1. 先验证已有 T07 是否真正可复用；缺少时作最小提取，并在 A minor 路由中保持视觉和行为。
2. 用已有 A major、C major 完整真实内容验证 T07 接口，补足本批需要的黑键、长标签、资源缺失等状态。不虚构第三份共用文案。
3. 实现 T06 中心页；键盘、声音、UI、打印机制复用，筛选与多结果状态属于中心自己。
4. 完成每条获批 URL 的内容/数据/功能检查及受影响页回归，再接受独立验收。

一个新模板先用一个实际代表页检查 Desktop/Mobile 和状态，再在同批接入其他实例。这是同一批内部检查点，不要求用户重新挑风格，也不要求每个按钮完成后暂停。

已有实现已满足以上要求就保留。只有一个使用者、职责简单的组件允许留在领域目录，不为了复用率拆碎所有 JSX。提取需要真实复用或独立测试/复杂行为依据。

## 7. 测试基建也是交付的一部分

优先复用已有测试工具和构建脚本。不默认新增 Storybook、可视化平台、状态库、表单库或通用页面引擎；已安装的 Storybook 等可继续使用。

需要覆盖：
- 原始内容到显示模型的正确映射、字段缺失和资源根路径；未知核心 block 不能悄悄忽略。
- 基础控件的键盘、focus、selected、disabled；加载/失败的独立处理。
- 音符/键位/事件/打印一致；等音与黑键边界；异步取消与快速连续操作。
- 多个键盘/表单/SVG 实例的 ID 不冲突；焦点与事件不串到别的结果。
- 模板接受不同真实对象，而非组件内部写死 a-minor。
- 1440/390 页面截图与 320/768 边界检查；共享 CSS 改动后复验调用页。
- 原始源文件哈希保持；noindex、受批次约束的路由与素材状态保持。

允许仅在测试运行器/本地测试产物中制作组件状态夹具，不增加生产展示路由，不复制原型作为业务页，不将内部材料放入 public。测试用例数据可模拟接口失败，但音乐内容从已提供真实对象取值。

单纯 build 通过、存在 components/ 目录或截图默认态，不构成组件基建通过。
