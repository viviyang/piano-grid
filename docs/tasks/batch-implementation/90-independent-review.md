# 90 — 独立验收（复用于每个批次）

你是独立审查者，不是第二个开发者。先读MASTER-RULES与实际AGENTS。
主开发对话在本轮审查期间必须暂停。用户未明确给出审查批次时，从site-implementation-plan中读取唯一“等待验收”的批次；若存在多个且无法判断，先问批次，不审成另一个范围。

## 权限与目标

可以读取源码、源资料、现有差异、运行测试/浏览器；可以写 `checks/reviews/<批次ID>/` 的报告/截图/日志。
不能修改产品源码、内容、样式、依赖、锁文件、AGENTS、检查断言、发布状态；不能自动修复、提交、推送或部署。
生成的.next等测试缓存不属于源码修改，但不得干扰正在运行的开发任务/端口。使用现有依赖，不自行安装新包。

## 流程

1. 读取进度表、当前批次任务、implementation.md及来源映射。记录本次实际工作区、HEAD（如有）与被审查未提交文件哈希。报告日期不能成为证明代码版本的唯一依据。
2. 对每个本批URL核对原规划final_scope、required_delivery、每个source_group的required_output、页面正文与数据/资源。开发方写“PASS”只是待验证陈述。
3. 逐页检查数据绑定，不只测代表页。不同schema与两个素材根是否正确；有没有把后台记录/整个master打入客户端或public；有没有把未授权路由随动态slug暴露。
4. 对比A minor改动前后与已验收视觉基线。不以个人审美更换主题；指出真正的文字拥挤、小SVG音名、横滚、焦点、状态问题。
5. 音乐工具检查图/音/打印同源、Root/Bass、升降与等音、黑键、停止/快速切换/方向；不能用源文件自检替代真实运行核对。未核验指法保持null。
6. 选曲/资源页面核对版本、难度依据、资源目标、使用权限，不能将正规外链误写为本站可再分发资产。
7. 核对1440/390真实页面及本批边界尺寸；自己运行现有check、相关测试与build（串行）；打不开或无浏览器就标NOT RUN，不引用开发截图当作自己测试。
8. 对依赖旧共享组件的A minor做回归；当前源码已经变更后不得只引用旧批次截图。
9. 不要求所有内容问题都重新研究，也不因无实物打印就一概否决本地实现；但核心数据错误、任务未交付、假下载、未授权资源、失效路由不能被放过。

## 组件与模板复用检查

依据 [COMPONENT-TEMPLATE-RULES.md](COMPONENT-TEMPLATE-RULES.md) 和实际源码，追加以下检查，不替代原逐页验收：
- 共享是否发生在实际 import/调用上，而不只是目录或文档；核对 component-spec 与 template-map。
- 同模板实例是否读取各自的内容和音乐数据，未写死 A minor 或以字符串替换生成假内容。
- 中心/详情/教程是否保留原任务，未被统一外壳抹平。
- 状态及数据所有权是否明确，避免大量 URL 特判和模式开关；多结果 ID、焦点、音频是否隔离。
- 服务器内容/metadata 与客户端交互边界是否正确，未把全站 master 打进浏览器。
- 是否过度重构、安装不必要依赖或提前生成未授权路由；共享代码修改后是否逐调用页回归。

## 报告产物

`checks/reviews/<批次ID>/review.md`

每个发现包括：稳定ID、严重程度P0/P1/P2/P3、URL、源任务/字段、代码位置、复现步骤、证据、影响、最小修复建议。
必须区分已复现错误、待验证风险、源内容遗留问题、视觉偏好。没有证据不要编造问题；无问题也要列出实际审查范围和未测部分。

结论仅为：
- PASS：没有阻塞本批实现的问题；源资料遗留门槛照旧。
- NEEDS_FIX：有可在已授权范围修复的问题。
- BLOCKED：缺核心资料/权限/环境导致无法判断或无法满足任务。

同时列明生产是否仍未发布、真实听音/设备/实体打印是否未做。不要把PASS当作用户视觉确认或上线批准。
若只有非阻塞建议，允许PASS_WITH_NOTES并解释，不用无限细节修改阻止后续批次。
完成后停止。报告交回唯一开发对话处理。
