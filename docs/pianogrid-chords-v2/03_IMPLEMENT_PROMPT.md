# Codex Prompt：PianoGrid 和弦系统分批实施

**本文件在用户明确批准审阅结果与某一批次后才生效。把文件放入仓库，或仅被Codex读到，不代表授权执行。**

## 使用方式

用户发送：

> 我批准 `docs/pianogrid-chords-v2/review.md` 中审阅通过的方案。本次只执行 **B1**。未列入已批准清单的删除、主题改动、依赖变更和新URL均不授权。请按 `docs/pianogrid-chords-v2/03_IMPLEMENT_PROMPT.md` 执行，完成本批后停止，不提交、不部署。

之后批准B2或B3时，在同一段话里更换批次。每次只执行明确指定的批次。用户修改审阅建议时，以最新明确修改为准，并记录差异。

## 给Codex的正式实施任务

先读取当前作用域的 `AGENTS.md`、`docs/pianogrid-chords-v2/01_PROPOSAL_v2.md`、`docs/pianogrid-chords-v2/review.md`，以及已有的 `implementation-log.md`。

若审阅未完成，或没有用户批准具体批次，不改代码，指出缺少的授权或基线。`READY` 不等于用户批准。

若工作区在审阅后有变化，先检查与本批相关的diff，更新主题/内容映射的受影响部分。不要对完全没变化的范围再做一轮全站研究。

### 不可放宽的要求

- 主题使用review中的实际基线；不从旧图取色，不改全站token、Logo、Header/Footer外观，不增加另一套近似主题。
- 正确内容与已可用能力全部保留，任何删除或纠错必须对应批准项。
- 四条现有URL、页面职责和正确metadata/canonical不变；不自动新增分类或详情路由。
- 用户可读正文与静态参考预渲染；不能为客户端交互把页面变成空壳。
- 复用原组件、数据、来源与校验系统；不全局重构、不升级依赖、不擅自更换工具库。
- 不覆盖用户已有改动，不reset/清理工作区，不自动提交、push、部署或更改DNS/GSC。
- 审阅后的设计判断可以小范围优化，但不得突破上述边界；确需突破时停在受影响事项，解释理由。

## B1：两种完整页面样板

### 目标

先让 `/chords` 与 `/chords/a-minor` 在真实代码、真实主题、完整正确内容下，呈现不拥挤的新版顺序和层级。

### 做什么

1. 按已有安全工作流隔离开发，不覆盖用户工作；使用当前原路由做本地/隔离预览，不创建公开可索引的设计稿路由。
2. 沿用review的主题与组件，依据内容映射移动章节，调整局部容器、间距、图与表的排布、按钮主次。
3. 保留读图说明、原理论、原定位步骤、原练习、FAQ、来源、全部资源说明、每种打印/播放功能及无JS内容。原有本页搜索、目录和锚点不默认删除。
4. 新增内容仅使用已准备并核对的材料。未就绪部分写在交互/内容规格里，不放假音符、假指法、假评分或无功能按钮。
5. 根音与类型已有实现时复用，不为画面好看增加不支持的类型；默认不创建大侧栏、全站搜索、收藏或移动底栏。
6. 无需在B1重写整个数据层或音频引擎，不批量重构另两个详情。共享组件改动必须确认影响并回归。

### B1交付

取得相同版本与视口的前后对照：中心桌面/手机、Am桌面/手机；附至少一个现有转位切换状态。实际查看截图，不仅保存文件。

报告内容保留情况、主题token/computed style对照、主要操作是否保留、尚待实施的新增交互。设计对比按相同元素与状态核对，不要求重新排序后的截图像素完全一致。

没有浏览器就标记“视觉未验证”，不能宣称设计定稿。样板不够合理要指出具体问题，不用继续缩小字号来勉强塞下。

**完成B1后停止，等待用户确认样板，不自动进入B2。**

## B2：最小Schema适配与详情复用

### 目标

在确认的页面样板基础上，复用一套可靠的数据和模板，覆盖现有三个详情，不丢内容或来源。

### 做什么

1. 按review决定复用现有校验器、增补约束或添加最小适配。已有结构足够就不重复建设。
2. 区分和弦定义、具体排列、指法案例、原页面内容、练习与资源/关系；逻辑职责清楚即可，不强制一个职责一个目录或数据库。
3. 保存原根音拼写、类型、音高和八度、来源/权利信息、审核状态、原正文模块与锚点。不能只导出JSON里最简字段，导致旧内容消失。
4. 三个详情共享模板，各自保留原有正确解释、FAQ、例子和资源。不得把Am正文复制后简单换字母。
5. 同一规范化排列驱动琴键、音名、低音、播放、打印及已支持谱表。新增公式/拼写算法必须有测试，不用统一升号列表或统一指法覆盖所有对象。
6. 保留现有静态生成/预渲染方式；按实际Next.js版本选API，不为动态路由迁移URL，不把整个工具设为`ssr:false`。

### B2交付

四页直接访问和原始HTML验证、无JS检查、原内容映射检查、metadata/链接、音符与转位/打印一致性测试；失败项逐项说明。

如需新增依赖或超出review的迁移范围，先提出最小理由，不自行安装。没有必要的架构改动可直接记录“复用现有，已满足”，不为了显示工作量重写。

**完成B2后停止，不自动进入B3。**

## B3：增量内容、交互与四页验收

### 目标

在原参考功能不退化的基础上，补齐审阅批准的学习与练习缺口。

### 做什么

- 根音×类型互相独立；选项与数量来自实际支持集合；清除、无匹配、读屏状态明确；不要用“未收录”冒充“这个和弦不存在”。
- 新增必要基础解释、左右手案例和一个带反馈练习。指法绑定排列、音区、手别、情境、来源和核查状态；无法核对的案例独立暂缓，不造数字。
- 原文字练习保留，新增练习有答题、反馈、重试和答案，明确判定组成音、最低音还是精确八度。不能声称判断了实际手指或实体钢琴演奏。
- 遵循提案交互表：播放/停止/切换同步、打印快照、实际PDF范围、目录锚点和真实详情链接。
- 当前说明与旧PDF内容必须区分；不因网页有新指法就给旧PDF换成“含指法”下载文案。
- 关系使用实际发布状态；不为做出一排推荐卡片增加失效链接。

### B3交付

四页桌面/手机、根音筛选、类型筛选、组合、清除、无匹配、每种转位、音频失败/停止、打印、无JS和关键读屏/键盘操作状态的验证。

首轮不支持的高级功能列为未交付，不自动扩大本批。实体打印、真机Safari、人耳试听、真实读屏没有执行时，明确列出待人工项。

**完成B3后停止。四页通过不等于自动授权部署。**

## 每个批次都执行的工作方式

### 开始前

简要说明本批文件范围、复用什么、哪些不动、如何验证。只在出现新增风险或授权冲突时询问，不对已批准的常规实现反复求确认。

### 实施中

小步提交到工作区、运行相关检查；不得用`--updateSnapshot`或修改期待值掩盖回归。不能删除失败测试以“恢复通过”。不要声称跑过未执行的浏览器、网络或音频检查。

有可证实的旧内容错误时按批准纠错清单修复。新发现的删除/主题例外不在授权内时，记录并保留其余工作，等待最小确认。

### 完成后

将结果追加到 `docs/pianogrid-chords-v2/implementation-log.md`，包括：

| 项目 | 需要写什么 |
|---|---|
| 范围 | 本批编号、基线版本、实际改动文件、原有用户改动 |
| 内容 | KEEP/MOVE/ADD/CORRECT/REMOVE对应原项；所有正确内容都有去向 |
| 主题 | 实际复用的token/组件与前后证据；有无新增色值或全局影响 |
| 交互 | 已可用行为、复现步骤、错误/空/无JS状态 |
| 测试 | 命令、结果、截图/日志路径；区分执行与未执行 |
| 问题 | 失败或待核对项、阻塞范围、没有顺手做的后续任务 |
| 停点 | 本批结论与下一步需要用户批准的事项 |

聊天回复只给：改了什么、为什么、验证结果、预览/证据位置和未完成项。不要输出一篇架构论文，也不要用“全部完成”替代真实范围。

**同一轮只做获准批次；不提交、不部署，不自动推进下一批。**
