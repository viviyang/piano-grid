# 首页视觉还原修复：只保留原配色，其他按参考稿

## 0. 本轮任务与指令优先级

本轮不是换一张 Hero 图片，也不是重新选择设计方向。目标是修复当前首页与参考设计在字体、材质、图示、布局、间距及响应式表现上的差距。

**只保留项目现有色彩系统；首页其他视觉属性按参考稿恢复。**

本文件替代 `CODEX_HOME_LAYOUT_ONLY.md`。撤销上一份指令中“首页必须沿用旧字体、圆角、阴影、按钮外形、扁平键盘外观”的限制；原路由、数据、发布边界、无障碍和未提交改动保护继续有效。不要把冲突指令叠加执行，不覆盖仓库 `AGENTS.md`。

授权范围限首页局部表现层。品牌名称、全站主题、内页与工具页默认不改。不能以“只保留配色”为由更换品牌、增加功能或重做内容规划。

## 2. 固定保留与明确可改

| 维度 | 本轮执行规则 |
|---|---|
| 页面底色、表面、文字、品牌强调、链接、状态色、焦点色 | 保留项目现有色彩系统，按真实语义 token 映射 |
| 字体族及角色、粗细、斜体、字号、行高、字距 | 首页按 V1 恢复，不受旧首页字体限制 |
| 容器、栅格、对齐、比例、留白、断点与换行 | 按 V1 恢复；Hero 摄影变体按第 4 节处理 |

“保留配色”不等于只能保留几个纯色块。黑白琴键的明暗层次、接触阴影和纸张投影可以使用与现有色彩体系兼容的中性明暗变化，但不要引入陶土色或暖金色品牌体系，也不要把整架黑键染成品牌蓝。

摄影素材保留自然色彩，不要求给照片整体加品牌蓝滤镜。

## 3. 实施方法：还原表现层，复用功能层

把原型中相关 DOM 层级、SVG 和 CSS 提取为首页局部组件或样式模块。可使用 `.piano-home` 作用域或 CSS Modules，按项目机制隔离字体与基础样式。

- 不导入原型 `body`、全局 `h1/h2`、`button` 等 reset；不全站修改字体、间距或按钮 token。
- 允许首页标题、按钮、面板使用独立视觉 variant；旧共享 Card/Button 外观还原不了参考时，不必硬套。
- 复用现有音频引擎、音高数据与交互状态。现有键盘的功能可以保留，扁平皮肤不必保留。
- 不把原型整套 JavaScript 再塞进项目，造成两套 AudioContext、事件绑定或重复键盘状态。
- 不重装/升级依赖，不 reset/clean，不自动 commit/push；保护现有未提交修改。

## 4. Hero：唯一有意区别于 V1 的区域

[已核实｜用户最新要求] 用户要窗边的三角钢琴、一双手、微风与优美窗外景色；不是让模型再次发送图片。

V1 的 Hero 原本是居中标题配立体键盘，没有摄影背景。本轮明确采用以下摄影变体，其他区域按 V1 还原，避免“完全复刻 V1”与“新增照片 Hero”两条要求冲突。

- 桌面：文字在左，摄影主体在右。为标题保留足够宽度，不把整段挤成狭长竖列。摄影主次是钢琴与双手，其次才是窗外风景。
- 仅在文字区域使用必要的局部遮罩；不要用高不透明度灰幕压暗整幅照片。遮罩要按现有配色和实际可读性处理。
- 使用已提供或项目已具备的窗边钢琴素材。找不到时报告准确的缺失项，不改用随机湖景，不让用户重复选择整个视觉方向。
- 手机：文案在上，照片在下，保证琴键与双手仍可见；不把桌面横图裁成无法识别主体的一条背景。文案和按钮不烧进图片。
- 摄影 Hero 下方独立放置 V1 的立体交互键盘。不要让白色教学面板遮住照片主体，也不要用照片替代交互键盘。
- H1 保持已确认文案，`Practice with purpose.` 恢复 V1 的衬线斜体角色。图上字色服从实际对比，不强行照搬原稿陶土色。
- 本轮不制作新照片或手部视频。静态图不等于风吹帘动的视频；没有真实素材时保持静态，不用整张照片左右摇摆冒充风。动画升级不是本次还原的阻塞项。

## 5. 逐区恢复，不允许省略图形

### 5.1 立体钢琴：恢复琴体，不是给平面键盘加外阴影

参考原 HTML 中 `.piano-stage`、`.instrument`、`.piano-fallboard`、`.keyboard`、`.white-key`、`.black-key`、`.black-key-shine`、`.piano-front` 与 `.piano-controls`。

需要同时存在：深色琴身外壳、上沿、前沿厚度、白键侧面与键缝、黑键顶部高光及落影、整架轻透视、落在承托面的阴影，以及真实高亮/按下反馈。移植材质层次时仅替换颜色，不删除渐变、阴影和透视结构。

[已核实｜V1 源码，非当前项目测量] 桌面 `.instrument` 上限 900px，使用 `perspective(1100px) rotateX(11deg)`；白键有内阴影，黑键有独立高光层与投影。这些说明立体感有可提取实现，不要求重新生成钢琴图片。尺寸与断点应整体参考源码，不孤立照搬一条 transform。

音名、正确键位、点击试听、键盘导航、焦点与减少动态效果保持可用。不可用一张截图冒充可操作琴键。

### 5.2 What do you want to work on?

恢复 `.task-grid`、`.task-illustration` 和每张卡片的 SVG：

- Chords：小键盘与和弦标记。
- Scales：逐步升高的音阶图形。
- Keyboard notes：音名与位置关系图形。
- Songs：乐谱式图形。
- Learn & practice：展开的书本。
- Tools & printables：纸张/谱线图形。

依真实入口匹配图示，不因顺序改变而贴错。桌面三列两行；手机按 V1 两列重排，图示完整保留。不是编号、箭头加大片空白，也不是用同一个小音符图标代替六种图示。

恢复标题合理占宽和图示区域高度，避免为了继承旧容器把标题挤成多个短行。顶部重复 Quick Actions 或旧入门提示块不应挤占主设计；原 V1 没有的旧首页模块不要未经判断全部堆回。

### 5.3 Change one note. Hear the difference.

参考 `.discovery`、`.discovery-copy`、`.chord-study`、`.study-notes`、`.interval-lines`。

恢复左右布局：左侧标题和说明，右侧和弦选择、音名、音程、试听。右侧不要再套一个 V1 没有的灰色后台面板。

`Change one note.` 用无衬线，`Hear the difference.` 用衬线斜体；不能只是减小粗体或在页面显示字面量星号。恢复 A / C / E 的大字、音程线与从属信息层级。

[已核实｜V1 源码] 宽桌面 `.discovery` 为 `1.13fr 1fr` 两列、`gap:65px`、上下内边距 63px / 左右 58px；原源码另有平板与手机覆盖。按整套断点恢复，不在所有宽度硬编码这些值。手机改上下布局，不能沿用桌面的窄列挤压。

### 5.4 Make room for a little music.

恢复 V1 两张编辑式封面：

- Songs：`A little music. Every day.` 的排版封面，含线条和音符图形。
- Reading：有投影与轻旋转的纸张、谱线和音符图形。

封面是上方视觉，`Find your next piece.` / `Read what you play.` 是下方标题与说明。不能合并成两张只有大字的纯色空卡。

提取现有 SVG/CSS，替换主题色即可；不要寻找随机图库封面，不把装饰谱线当成可供练习的完整谱面。

### 5.5 资源区、页尾与排版细节

保留 V1 的列表与图文节奏。页尾使用 V1 三角钢琴插画，不重复塞同一张 Hero 照片，也不临时添加第三种插画风格。

[已核实｜V1 源码] 无衬线栈为 `ui-sans-serif, system-ui, -apple-system, BlinkMacSystemFont, 'Segoe UI', sans-serif`，局部衬线为 `Georgia, 'Times New Roman', serif`。两者是角色组合，不是全站改成衬线。不得凭概念图另引入 Playfair、Caveat 等第三套字体。

[已核实｜V1 源码] 主内容上限 1120px；通用章节桌面上下内边距 92px、手机 57px。实际各区存在例外与断点，应从源码提取。不要依据缩放后的长截图反推 CSS 像素，也不要靠浏览器缩放冒充响应式调整。

检查实际计算字体、字重、行高和 letter-spacing，查明是否被 prose / typography / 共享组件样式覆盖。不能根据截图先断言具体是哪个 CSS 规则造成的。

## 7. 执行与验收

先简要列出“当前差异 → 对应参考选择器/资产 → 修改文件”，随后实际修复，不停留在审查报告，不再另出新的风格方向。

建议顺序：排版和容器 → 立体键盘 → 六个任务图示 → 大小调区 → 两张封面与页尾 → Hero 摄影变体与移动端收尾。

在原型与项目可运行时，用同一浏览器、1440px 和 390px CSS viewport、100% 缩放、字体就绪及相同动画定帧做对照；补查 320px、768px 溢出和布局。除了明确授权的 Hero 变体，其他区域逐区核对：

1. 字体角色、粗细、斜体、换行与标题占宽。
2. 容器、模块内外间距、列比例与对齐。
3. 立体键盘各材质层是否完整，交互是否真实。
4. 六张任务图示、两张封面与页尾插画是否确实存在。
5. 原项目色彩体系是否保留，是否残留原稿陶土强调。
6. 控件焦点、触控、试听、菜单与减少动态效果是否正常。

不同配色下不要求全图像素差异归零；字体跨系统也可能不同。颜色差异不是删除图示、改变布局和丢失斜体的理由。截图渲染正常不等于功能、听音或无障碍全部通过。

将最终桌面/手机截图、逐区检查、修改文件、实际运行的命令及未测项保存到项目现有验收位置。回归至少一个现有内容页和工具页，确认首页局部样式未污染它们。不能沿用旧原型的“28 项通过”声称本次集成通过。

**完成标准：保留原项目配色；首页字体、图示、封面、材质、比例与间距按 V1 还原；只有 Hero 按最新窗边钢琴方向作明确变体。不能用“模块顺序对了、页面能运行”代替视觉验收。**
