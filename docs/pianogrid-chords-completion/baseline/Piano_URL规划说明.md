## 3. 页面分工：游戏方法只借原则，不照搬内容

| 层级 | 本项目职责 | URL示例 |
|---|---|---|
| 首页 | 解释网站帮助用户完成什么，引导已上线的任务；不强行把`piano`泛词作为主排名目标 | `/` |
| 工具中心 | 按查键、和弦、音阶、打印等实际动作组织工具 | `/tools` |
| 内容/资源中心 | 按曲目、难度、谱面资源或学习路径组织内容 | `/songs`、`/sheet-music`、`/guide` |
| 具体工具 | 进入即能查、选、播放或打印，满足明确任务 | `/chords/a-minor`、`/scales/c-major` |
| 曲谱资源页 | 明确版本与获取方式，实际提供可用资料；不以纯文章冒充下载 | `/sheet-music/twinkle-twinkle-little-star` |
| 方法文章 | 解决“如何学、如何练”，配真实示例并连接工具 | `/guide/read-sheet-music` |

[推断] 以上是一个网站的页面分工，不是拆成多个网站。首页只展示已经准备好的能力，未完成的曲谱或教程中心不发布空目录。

## 4. 同页还是独立页：本次具体处理

| 原任务 | 规划处理 | 边界 |
|---|---|---|
| 琴键数量、八度、单个音名、黑白键定位 | `/keyboard-notes`的可查询图表和说明区 | A4/F3等小对象先由统一工具展示，不自动各做短文 |
| 61/88键标注、打印标注图、如何贴标 | `/keyboard-notes/labeled`的键数模式、打印和步骤 | 61键、88键不是同义，但可以共用一个满足各条件的工具 |
| 琴键与高低谱号对照、do re mi显示 | `/keyboard-notes/chart` | 谱表映射与单纯标注键盘的交付不同；唱名体系需说明 |
| Am、A major、C major和弦 | 不同具体和弦URL，共用基础组件 | 只对数据已有对象规划；不自动生成全部根音×品质×转位组合 |
| major/minor/7th和弦图、打印、读图 | `/chords`的类型筛选和说明 | 不为每种图表格式复制页面；7th不能改成major7 |
| 调内各级和弦 | `/chords/by-key`统一调性选择表 | 和“某一个和弦怎么按”不同；各调先用同页查询承接 |
| 音阶chart/pdf/online/fingering | `/scales`的图表、指法和打印功能 | 具体调性的独立页仍可保留；不是全站只有一张音阶表 |
| 初学歌曲、儿童/成人条件、效果出众等 | `/songs/easy`分区或筛选 | 同页覆盖不是把这些条件当同义；需要实际相应曲目 |
| Jingle Bells原谱/初学版/字母音名 | 同曲一页分版本 | 必须明确同一作品和可用版本；不是擅自改编或假装已清权 |
| grade 1/2、若干同名曲和含糊记谱词 | 暂不分配URL | 不先补写考试机构、歌手或未验证关键词 |

[推断] 场景筛选、难度与格式可以帮助组织内容，但不必每个筛选值都有独立URL。反过来，输入、输出或具体查询对象确实不同且能提供差异内容时，独立页是合理的候选。

## 6. URL和抓取实现边界

[已核实] Google官方建议使用简单、可理解的URL，并说明通常不支持用fragment作为改变页面内容的路由。[G1]

[推断] 本项目采用小写、短横线和描述性路径；音乐升号使用`sharp`，降号使用`flat`。`/scales/a-sharp-minor`与其他等音拼写不在本轮强行合并。表格中的分区ID只是定位已经显示的正文，不是额外的搜索落地页。

[已核实] Google官方建议通过可抓取的链接连接页面，不能指望爬虫提交站内搜索；参数化筛选可能形成巨大的URL空间。[G2][G3]

[推断] 中心页直接链接已发布的具体页；筛选状态、同页章节、打印按钮不自动形成一套新的可索引路由。后台或前端数据未准备好时，不发布空路由，也不输出到线上sitemap。关于/联系/隐私等基础信息页如后续需要，另列非获客需求，不能为它们虚构搜索量。

[已核实] 使用模板或AI批量生成没有新增用户价值的页面，可能违反规模化内容滥用政策；满足基本要求也不保证索引或排名。[G4][G5]

[推断] 此处没有套用附件中“所有内页写1200字”“一定10–20页”“游戏主词全部由首页争夺”等具体做法。Piano的工具、谱面资源和教程需要不同交付，不强制全变成文章。
