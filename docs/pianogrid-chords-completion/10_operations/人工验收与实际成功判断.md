# 人工验收与实际效果：不能由代码代签

## 发布前一次集中做
同一production build记录commit/日期/设备/浏览器，不为每批重做重复全套。
1. 人耳：C、Am、Cdim7、C7、Cadd9、C13（全式/省略）、C7(♯9)；对照理论音列，听齐奏/逐音/Stop与切换；不以按钮状态测试代替听到的声音。
2. 真机：iPhone Safari为必选；可获得时Android Chrome。完成查C13→试听→练习→Finder多结果→打印参考整条链，不仅截图首页。
3. 读屏：Windows可用NVDA配Firefox/Chrome，iOS可用VoiceOver。记录实际软件与版本；检查输入、所选琴键、低音、结果数、错误、reset、导航返回焦点。
4. 打印：US Letter与A4至少各一个代表；检查Extended多页、变音符、页码/边距、当前例子是否对应；字体/标签不正确不能写PDF无障碍PASS。
5. 音乐复核：教师或具备相应能力的独立审阅者抽核C13省略、C11(no3,no5)、major11自然11、C7(♯9)、A♭dim7、C6/Am7命名、小调V7变化。只审过这些例子就只声明这些例子，不声称全部433对象教师通过。

没有设备或审阅者时，记录pending和真实风险；不自动把它变成开发失败，也不能宣布“完全验收”。若发现wrong notes、错误反馈、无法停止音频、核心控件不可用，是发布阻断。

## 真实用户观察（建议）
找5位目标用户做5个任务：查Am；解释指号与C4；用输入音找Csus2/Gsus4候选；听C13当前省略；完成C→Am/C练习并打印。
目标建议：至少4位可在不经口头指导的情况下完成关键路径；查音入口约一分钟内找到。小样本只用于发现问题，不是市场规模/转化率的统计证明。
记录失败步骤、原话和实际耗时，不编访谈，不让Codex写“用户很喜欢”。修最高影响的3项，再观察。
